# Mac.apk 本地兼容性升级：2026-10-28 进度快照

本分支保存完整项目源码，以及 DSH、Antigravity、Workbuddy、Codex 在本地接续开发的最新进度。它是**开发快照，不是已完成验收的稳定发行版**。弹幕尚未修好；某些实验组合仍可能黑屏、闪烁或在全屏切换后残留画面。

目标是在 macOS 上实现通用 Android 应用兼容层，尽量复用原生窗口、GPU 和 VideoToolbox，而不是为每个 APK 修改业务代码。Bilibili 是当前主要回归样本，不能据此推断其他应用全部兼容。

## 尚未解决的问题

1. **弹幕未显示。** 原生渲染循环有回调但只观察到一次 EGL swap。独立透明 Surface 曾遮住视频；保留 alpha 的隔离实验恢复了视频，但没有恢复弹幕文字。不能继续把“视频正常”当成“弹幕已修复”。
2. **黑屏有多个原因。** 参数集解析失败与图层不透明/坐标/路由问题必须分开排查。H.264 参数修复应保留；后续不能用旧版 native 二进制覆盖掉它。需记录实际 APK、runtime/JAR 标识、视频 ID、编码和清晰度。
3. **全屏与 Surface 生命周期没有完整验收。** 竖屏进入/退出、横屏旋转、旧图层、owner 更新、窗口隐藏、切换清晰度和多视频实例都可能暴露旧状态。
4. **图标未完全正确。** 返回图标部分恢复；编辑按钮可能为叉号。PUA 字体优先级启发式不等于正确的字体资源身份，不能通过重映射 Bilibili 字符码掩盖框架问题。
5. **性能仍需测量。** 常规 pbuffer 路径仍可能 GPU→CPU 回读；独立运行曾有约 650–900 MB RSS、数十个百分点 CPU。数字来自不同场景，不能与 iOS 客户端直接比较，也不能据此宣称功耗改善百分比。字体强引用身份缓存还应检查增长上限。
6. **酷安评论区闪退、加壳应用兼容仍未解决。** 完整模拟器通常提供更完整的 Android 系统环境；兼容层需要逐项补足框架/JNI/Bionic/加载器语义。早期脱壳或重打包成功不等于原始 APK 可以直接运行，也不能保证任意壳能加载。
7. **发布源码与机器上正在使用的应用不是同一个已核验产物。** 先前实验发生过构建脚本自动同步，然后回退到较早 native；回退产物不是之前仅修复 csd 的那个版本，可能不含当时修复。不要凭应用名或 Dock 图标判断版本。详见验证记录。

## 实验开关与归档

以下只用于隔离测试，不应直接作为正式安装默认值：

| 开关 | 作用 |
| --- | --- |
| `MACAPK_EXPERIMENTAL_NATIVE_SURFACE_LAYERS=1` | 按 Surface 建立原生图层/窗口路径 |
| `MACAPK_EXPERIMENTAL_PRESERVE_SURFACE_ALPHA=1` | 保留透明 holder 的 Metal layer alpha 语义；与上项组合测试 |
| `MACAPK_EXPERIMENTAL_ALPHA_PROBE=1` | 透明与像素诊断 |
| `MACAPK_EXPERIMENTAL_SURFACE_BELOW_VIDEO=1` | 图层顺序 A/B，不能用作最终遮罩修复 |
| `MACAPK_NATIVE_CHOREO_TRACE=1` | 原生 Choreographer 计数/耗时 |

`MACAPK_ANGLE_BACKEND=metal` 仅用于和 Vulkan 对照，不是默认解决方案。当前没有 `MACAPK_NATIVE_CHOREO_WAKE` 功能。

[archived-experiments](archived-experiments/README.md) 保存另一开发树的 P0、异步 owner 调度、限流等补丁与风险说明，**没有应用到当前 runtime**。它们以历史基线为目标，和本分支已有修改会冲突，禁止整包覆盖。部分建议已被后续证据推翻。
