## 1. Governance Principles

1. **Diagnostic / Experimental Gates != Verified Capabilities**: Having an environment gate (`MACAPK_*` or `DEX2JVM_*`) does not count as capability readiness. Capabilities live in [`capabilities.json`](capabilities.json) and require contract tests (`scripts/run_tests.py` + `debug/FeatureGatesTest.py`).
2. **No Forced Runtime Single-Registry Overhead**: Hot-path flags remain `static final` constants (Java) or `static const bool` / direct `getenv` checks (C++/ObjC). Consistency is enforced via [`feature_gates.json`](feature_gates.json) + `validate_gates.py` rather than introducing runtime lookup overhead.
3. **Init-Sensitive Gates Require Fresh Subprocesses**: Flags cached in `<clinit>` (`PresentedSdk`, `Build.VERSION`, `NativeLog`, `Log`, `ServiceRegistry`, `Choreographer`, `DexFile`, `Resources`, `SurfaceView`, `Bitmap`, `DexConverter`) or process startup (`SystemClient`, `macapk-runtime`) must be verified in brand-new subprocesses with scrubbed environments, never by mutating `env` inside an already-initialized JVM.
4. **Classification (`kind`)**:
   - `experimental`: Transitional implementations behind opt-in/launcher toggles awaiting promotion thresholds (`GATE-002`).
   - `behavioral`: Core runtime/ABI/broker behavior switches.
   - `compat_opt_out`: Production-ON compatibility normalizations or fast-paths with `=0` kill switches.
   - `diagnostic`: Logging, tracing, and verification-only flags.
