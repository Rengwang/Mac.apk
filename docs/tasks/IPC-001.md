# IPC-001：修复 Binder 调用身份与远端服务契约

- 状态：DONE
- 前置：ARCH-001、CI-001
- 证据目录：`work/upgrade/IPC-001/`

## 目标与修复范围

1. **`Binder.getCallingUidOrThrow()` 非事务上下文契约（`GAP-IPC-002` / `CTR-IPC-XFAIL-002`）**：在 `runtime/java/android/os/Binder.java` 中跟踪当前线程是否处于入站 Binder 事务分发（`sTransactionDepth`）或显式清空身份（`sExplicitIdentityDepth`），在非事务上下文调用 `getCallingUidOrThrow()` 时按 AOSP 契约抛出 `IllegalStateException`，在 `transact()` / `onTransact()` 或 `clearCallingIdentity()` 之后正常返回 UID，并将 `contract_baseline.json` 中 `CTR-IPC-XFAIL-002` 翻转为 `PASS`（至此契约套件 14 项全绿）。
2. **跨进程 `:worker` 路由与回归**：在 `runtime/java/android/os/MacApkBinderTransport.java` 中入站跨进程事务派发同步维护 `sTransactionDepth`，保持 `ProcessBrokerRoutingTest`、`BrokerServiceStartupTest`、`RemoteBindCompletionTest`、`ParcelBinderTransportTest` 全部通过。
3. **同步 `ServiceRegistry.bind` 跨进程 `:worker` 闭环（`GAP-IPC-003`）**：
   - 在 `runtime/java/com/macapk/loader/SystemClient.java` 新增 `IN_BROKER_BIND`、`LAST_REMOTE_BIND_HANDLED`、`bindBlockingIfRemote(Context, Intent)` 与 `consumeRemoteBindHandled()`，并在 `AppThread.onTransact(TX_SCHEDULE_BIND)` 中保护 `:worker` 目标进程不回弹至 broker；更新 `runtime/java/android/app/ServiceRegistry.java` 的 `ServiceRegistry.bind(Context, Intent)` 优先走 `SystemClient.bindBlockingIfRemote`，无 broker 或本地目标时回退到既有 `ensure(ctx, cls)` 行为。
   - 在 `runtime/java/com/macapk/loader/SystemServer.java` 提取 `terminateSpawned(long)` 并在 broker 测试模式下注册退出钩子清理子进程、创建 `MACAPK_BROKER_LOGDIR` 目录且避免向子进程透传 `MACAPK_BROKER_READY_FILE`。
   - 新增无头多进程 broker 回归脚本 `debug/run_remote_service_broker_test.py`，在临时目录用 `apktool` 构造含 `android:process=":worker"` 的测试 APK 并通过瞬态 `LaunchAgent`（`org.macapk.system.test.<pid>.<rand>`）启动 `SystemServer` + `macapk-runtime` 驱动 `debug/RemoteServiceProcessTest.java`，退出前无条件 `launchctl bootout` 并清理工作进程。
