## 数据与决定

- 在各自独立 Android root 对同一 COMP-001 H.264 五帧 `VideoImageSelfTest` 交替实跑。每个 collector 一轮预热、三轮正式。两端都使用 `MACAPK_WINDOW_FIRST=0 MACAPK_AWT_MAIN_INIT=0 MACAPK_VIDEO_IMAGE_SELFTEST=1`。Serial 组 `MACAPK_JVM_OPTS="-Xlog:gc"`，G1 组 `MACAPK_JVM_OPTS="-XX:-UseSerialGC -XX:+UseG1GC -Xlog:gc"`。JVM 日志确认各自只有一个 collector，8 次自检全部 PASS，rc=0。
- 正式三轮 Serial/G1 墙钟中位 0.70/0.68 s，三轮范围 0.67–0.71 / 0.68–0.69 s；峰值 RSS 中位 452.98/419.39 MiB；采集的最长单次暂停为 8.929/2.273 ms（HotSpot GC 行）。独立本机日志 `serial-*.log` / `g1-*.log`。当时 JARS_ID `787b03ba107af00f`；GC 复用相同构建，`jvm_loader.cpp` 已支持显式停用 Serial。
- G1 默认值评估 no-go。此短负载的暂停与 RSS 改善不能覆盖曾出现 JNI/ARM32 根扫描错误的场景，墙钟变化也在波动内。继续使用现有 Serial 默认；长期 JNI 和 GUI 数据为 NOT_RUN。
- `python3 scripts/run_tests.py --group offline --strict --out-dir work/upgrade/GC-001/offline` 42 PASS、0 FAIL、0 SKIP、15 NOT_RUN，rc=0。
