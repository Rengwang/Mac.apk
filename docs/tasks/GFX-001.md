## 2026-11-04 缓存原型验证

已在不改变 AOSP 配置回调语义的前提下实现三层进程内缓存：解析后的 APK ARSC 表、

首次进入全屏和首次旋转横屏的实测变化：

| 切换 | 基线 ResourceIndex | 缓存原型 ResourceIndex | 结果 |
|---|---:|---:|---|
| 进入全屏 | 847 ms | 224 ms | 已解析表复用；资源选择 39 ms |
| 首次旋转横屏 | 962 ms | 414 ms | 已解析表复用；资源选择 19 ms；framework view 仍为首次构建 386 ms |

## 2026-11-04 Surface 布局提交 A/B

尝试在窗口完成一次 `measure/layout` 后立即同步收敛全部 SurfaceView，以消除下一帧
才提交最终尺寸的延迟。该实验只作为显式开关运行，没有保留为默认行为，因为日志证明
提交时布局尚未收敛：

```text
live-resize 3420x1924
swapchain 1208x680
surfaceChanged 3420x680
swapchain 3420x680
surfaceChanged 3420x1440
swapchain 3420x1440
```

也就是说，过早提交把原来的两次交换链变成了三次，增加了重建和短暂空档，属于负结果。
正确的跨帧 transaction 必须等 B 站完成后续 layout，期间继续保留最后一帧，只把最终
Surface geometry 发布给播放器；不能简单把现有的“下一帧收敛”提前到当前 layout 返回点。

## 2026-11-04 Surface geometry transaction 原型

在 `surfaceChanged` 前开启、在 `macapkDrawFrame()` 后结束一个默认关闭的 geometry
transaction，并让非主线程的 `CocoaSetNativeEglBufferGeometryForSurfaceKey()` 在事务
期间有限等待。内建 Retina Display 上完成竖屏全屏、横屏、竖屏、再次横屏和退出全屏。

关键结果：

- 首次横屏仍执行 `ResourceIndex rebuilt ... land in 373ms`；第二、第三次分别命中
  已缓存配置，重建均为 `0ms`。
- transaction 的 begin/end 顺序正常，日志中的交换链均直接使用最终
  `1280x720` 或 `720x405`，未出现本轮之前的旧尺寸中间交换链。
- 当前内建屏路径中，B 站数秒后才触发 renderer geometry，调用发生在 transaction

## 2026-11-05 BitmapShader 形状烘焙缓存与滚动验证

`Canvas.drawPath()` 的圆角图片使用 AOSP `Canvas + BitmapShader` 语义，不按包名、类名或资源 ID 分流。仅当抗锯齿开启、alpha 为 255、无 ColorFilter/BlendMode/XferMode、SrcOver、正向轴对齐、整数设备原点且形状完全落在源图映射内时，先把 Skia 采样缩放到目标设备尺寸，再把最终抗锯齿路径烘焙成一张 ARGB 图。滚动只改变整数设备原点时，后续帧使用设备空间 1:1 blit。

缓存键包含 Bitmap 身份、`generationId`、输出尺寸、缩放、过滤、路径几何与 winding rule、抗锯齿；不包含 Canvas 绝对平移。总容量 32 MiB，单结果最多 400 万像素。`Bitmap.recycle()` 立即丢弃对应结果，框架的 `Application.dispatchLowMemory()` 和 `dispatchTrimMemory()` 会先清理缓存再通知应用。`MACAPK_BITMAPSHADER_SCALE_CACHE=0` 可关闭；关闭 `Bitmap.GENID` 时缓存自动禁用。

- PASS：更新后的 `ContainedBitmapTextureTest` 共 80 项精确门控；同时覆盖路径命中/未命中、generation 变化、recycle、显式 discard、trim、32 MiB LRU 淘汰和通用 `Path2D`。
- PASS：`BitmapShaderSamplingTest -XX:-DoEscapeAnalysis`，1,297,757 次像素对照全部相等，50 万次采样 0 字节分配。
- PASS：独立大窗口（请求 1162×2034，Surface 1190×2084）进入真实“热门”页并连续合成 20 次 precise-scroll；进程无崩溃，末段缓存 `hits=5083/misses=37`，形状缓存 `5071/19`，约 99.3% 命中，常驻 18,937,872 bytes。滚动帧走现有 partial damage，观测区域约 33%–39%，没有采用整帧平移近似。
- 诊断限制：该冒烟启用了缓存统计，且信息流内容和视频帧持续变化；命中率和 partial damage 只能证明路径被使用，不能作为产品 FPS 或最终流畅度验收。横屏全屏、旋转及音画连续性仍 NOT_RUN，GFX-001 保持 PENDING。
- 外部建议取舍：当前形状键本来就不含绝对窗口坐标，不能改成只含圆角半径和尺寸，否则无法区分任意 Path；按 dy 整体平移上一帧涉及悬浮层、透明混合、动画和 under-damage，本轮未采纳；“滚动期禁止 layout”违反 AOSP `requestLayout` 契约，不采纳；fling 降采样与 Skia Metal 作为后续独立 A/B/项目，不与本缓存混做。

证据：`work/upgrade/GFX-001/smoke-r8.log`；原始测试输出保留在会话日志，不提交生成目录。
