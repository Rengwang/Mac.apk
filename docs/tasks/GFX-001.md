## 问题根因与已合入修复（截至 `21c7a6e`）

1. **配置/旋转停顿主因已修复（`326979c`）**：`ResourceIndex.macapkBuildFwViewUncached` 在冷配置切换（横屏旋转 / 暗色模式）时重复解压约 52 MB `resources.arsc` 并全量重跑 `ArscReader.parse`；现引入不可变 `MacapkFwParsed`（`idHash` / `byCfg` / `thresholds`）经 `SoftReference` 复用并无条件填充 `sFwThresholdCache`（隔离 `ResBench` 实测：`land1` `160→18ms` -88.7%，`night1` `121→12ms` -90.1%；`ResourceIndexRotationTest` PASS）。
2. **缩放与 Surface 生命周期修复**：已合入显式 free-window 尺寸沿用、`SurfaceView` keyed pull 刷新已提交 Display 尺寸，以及 `SURFACE-001..003` / `SCHED-001` / `GPU-001`（旧连接迟到帧隔离、IOSurface slot 事务保护、代际变更淘汰旧呈现、透明像素 NEON 上载）。
3. **4 GiB 返回别名窄恢复与 Sidecar 进程清理检查点**：针对竖屏全屏 `StoryTransparentActivity -> ViewCoordinator.attachToNative` 触发 `libchronos.so+0x1bd76c` SIGBUS（`pc == lr == si_addr == corrected + 0x100000000`、`mov x0, sp; bl ...`），在 [guest_return_alias.h](../../runtime/translator/src/guest_return_alias.h) 扩展 `SetupBl`（`0..3` 条无访存/不读写 `x30` 不写 `sp` 的纯 setup 指令后紧接直接 `bl`）及 `RestoreLr`（补齐无符号偏移 `ldr x30, [sp, #uimm12]` 与 64 位 `ldp`），在 [bionic_shim.cpp](../../runtime/translator/src/bionic_shim.cpp) 将 `MACAPK_RECOVER_4G_RETURN_ALIAS` 改为默认开启并同步修复 `ss.__pc` 与 `ss.__lr`（扩充 [GuestReturnAliasTest.cpp](../../debug/GuestReturnAliasTest.cpp) 单测）；同步强化 [sidecar_runner.swift](../../debug/sidecar_runner.swift) 在 `quit`/`launch` 清理时按 `<bundleId>` 精确回收残留 `macapk-runtime` 子进程（如 `:ijkservice`）。待 Sidecar 竖屏全屏实机复测通过后方可关闭本卡。
4. **跨进程 IOSurface 异步呈现、4 槽原生帧环与 TextureView 零回读直通检查点**：[Surface.java](../../runtime/java/android/view/Surface.java) 在 `MACAPK_REMOTE_SURFACE_ONEWAY`（默认开启）下将 `TX_PRESENT_IOSURFACE` 改为 `FLAG_ONEWAY` 非阻塞发送并在 `SurfaceSinkBinder` 中保证即使 `!mOwner.isValid()` 也安全消费/释放 Mach 端口；[SurfaceTexture.java](../../runtime/java/android/graphics/SurfaceTexture.java) 将单槽 `mVideoNativePixbuf` 升级为有界 4 槽 FIFO 环并在 `updateTexImage()` 后仍有余量时续投 `mOnFrameAvailableHandler` 避免 60fps 连续帧被覆盖丢弃；[SurfaceView.java](../../runtime/java/android/view/SurfaceView.java)、[TextureView.java](../../runtime/java/android/view/TextureView.java)、[MacApkGlWindow.java](../../runtime/java/javax/microedition/khronos/egl/MacApkGlWindow.java)、[MacApkEGL10.java](../../runtime/java/javax/microedition/khronos/egl/MacApkEGL10.java) 与 [egl14_bridges.inc](../../runtime/src/egl14_bridges.inc) 在 `MACAPK_TEXTUREVIEW_DIRECT_GL_LAYER`（默认开启）下为可见对齐 `TextureView` 的 `EGL14` / `EGL10` 窗口绑定独立 keyed `CAMetalLayer` + `Canvas.punchHole`（无宿主层时自动平滑回退 pbuffer），消除每帧 9.15 MB 同步 `glReadPixels`。
5. **尚未关闭**：`ed9698e + 2d1da57` 合入 promote（`261118.1447-24a8f2a+dirty`）后，[SurfaceTextureNativePixbufTest.java](../../debug/SurfaceTextureNativePixbufTest.java) 与 [TextureViewDirectVideoTest.java](../../debug/TextureViewDirectVideoTest.java) 离线/GPU 通过，Sidecar 25s 播放实测显示 `EGL10` `SurfaceView` 走 `direct CAMetalLayer`，但 `EGL14` `Surface(SurfaceTexture)` 仍回退 `pbuffer-backed window 0x1`/`0x3`；新构建上的横/竖全屏往返与 30 秒切换连续性尚未重测（`NOT_RUN`；前序 `1137943`/`93c581df` 曾完成 Wave-3 全屏切换实测）。
