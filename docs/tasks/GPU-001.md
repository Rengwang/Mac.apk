# GPU-001：局部绘制或冗余 readback 热路径优化

- 状态：DONE
- 前置：ARCH-001、PERF-001、OBS-001
- 证据目录：`work/upgrade/GPU-001/`

## 目标与修复范围

针对已定位的单一绘制/拷贝热点（如 `VideoImageSelfTest` / `NativeVideoImage` BGRA→YUV 转换拷贝、重复 BitmapShader 采样或冗余 `glReadPixels`）实施局部可逆优化，保持像素输出与生命周期契约不变。

## 允许修改文件

- `runtime/src/video_pixels.h`（现有像素转换内核）
- `runtime/java/android/graphics/`、`runtime/java/android/media/MediaCodec.java`、`runtime/src/cocoa_bridge.mm`、`runtime/src/native_media.cpp`
- `debug/BitmapShaderSamplingTest.java`、`debug/ContainedBitmapTextureTest.java`、`debug/VideoPixelsTest.cpp`

## 构建与验收命令

1. 离线构建：`MACAPK_NO_BUNDLE_SYNC=1 runtime/scripts/build.sh`
2. 回归与前后对比：`python3 scripts/run_tests.py --group offline --strict` 及同条件微基准前后耗时对比（免除 30 分钟长跑与强制多进程 Sidecar ABBA 矩阵）

## 验收与回退

- [x] 相关像素/渲染单测与 `offline` 组全部 `rc=0`，同条件指标有实测改善且无回退。
- **回退**：`git revert` 本卡提交并重跑离线构建。


## 实现与证据

- 基点 `66030e2`。选定 SurfaceTexture 的直通 ARGB → RGBA JNI 上载中的半透明 premultiply 分支。参考 [libyuv 的 ARM64 补色内核](https://chromium.googlesource.com/libyuv/libyuv/+/refs/heads/main/source/row_neon64.cc) 的交错读取思路，沿用本项目精确的 round-to-nearest 除 255 算法，每次处理 8 像素，保留标量尾部和非 ARM 路径。没有引入依赖。
- 本机 `clang++ -std=c++17 -O3 work/upgrade/GPU-001/swizzle_bench.cpp -o work/upgrade/GPU-001/bench-after`，同进程交替比较 1920×1080、stride=1936、固定混合 alpha、每组 40 次预热 + 180 次采样、4 组。转换耗时每帧 0.9521 ms → 0.3080 ms（中位数），范围 0.9517–0.9639 → 0.3065–0.3087 ms；非 premultiply 0.2186 → 0.2166 ms。是 CPU 像素准备耗时，GPU 执行及真实显示 FPS 未采集。原始结果 `before.log` / `after.log`。
- `MACAPK_NO_BUNDLE_SYNC=1 runtime/scripts/build.sh` PASS，rc=0；`python3 scripts/run_tests.py --group offline --strict --out-dir work/upgrade/GPU-001/offline` 42 PASS、0 FAIL、0 SKIP、15 NOT_RUN，rc=0。含 `VideoPixelsTest` 的精确颜色、alpha 舍入、奇数宽、行方向、stride 和 guard。下一张 [CACHE-001](CACHE-001.md)。
