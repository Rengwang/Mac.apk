## 目标与范围

建立明确的现状和后续隔离方案，暂不改变默认签名/权限/运行模式。
检查 launcher、stub、runtime、共享 payload、JIT/native loading 和宿主文件访问的边界。

允许：新增 [docs/adr/0002-sandbox-and-isolation-boundaries.md](../adr/0002-sandbox-and-isolation-boundaries.md)、更新本任务卡、在 `work/upgrade/SEC-001/` 保存无敏感验证证据。
不包含：修改默认签名/entitlements/源码、直接实施 App Sandbox、修改 `docs/UPGRADE_PLAN.md` 或 `PROJECT_STATE.md`（由整合阶段统一更新）。

## 步骤

1. 以 `SECURITY.md` 和实际进程/entitlements 为依据记录当前权限，不假设已有 APK sandbox。
2. 使用专门的无敏感 canary 文件验证必要边界，不访问浏览器资料、密钥或个人文档来“证明风险”。
3. 核实 App Sandbox 等候选与 JIT、动态库、`custom-x18-abi-toggle` entitlement、生成 bundle 模式的约束。
4. 官方平台资料与实际可行性实验分别标明；需要实验时放独立环境，不修改日常签名。
5. 在 `docs/adr/` 新增评估记录：现状、威胁、候选、限制、后续试验和 go/no-go 条件。
6. 核查文件选择授权、security-scoped bookmark、生成 app 身份、broker/子进程与共享 runtime
   是否会跨越预期边界。无环境验证的签名/JIT/sandbox 组合明确留待独立试验。
   本任务的目标是评估，可以在不能实施 sandbox 时完成有证据的 no-go；不能宣称隔离已实现。

### 评估结论与未覆盖范围

- **决策（NO-GO）**：详见 [ADR-0002](../adr/0002-sandbox-and-isolation-boundaries.md)。当前“ad-hoc 独立 `CFBundleIdentifier` 生成包 + `execv` 外部共享 runtime + 共享 `~/Library/Application Support/Mac.apk/` + 无 TeamID `launchctl` 回退”架构不可直接开启 `com.apple.security.app-sandbox`。
- **未覆盖范围**：未在开启 `com.apple.security.app-sandbox` 的环境下实测 `TPIDR_EL0` bit 48、`jit_wx_guard`、`guest_jit_pages` 或 `SMAppService` + App Group Mach IPC（已明确标为未验证，留待独立 `SEC-002` spike）。
