## 实现与验证（2026-11-14）

- 从 `f921679` 继续。复用现有 `Resources.getValue` 的别名、配置和 APK cookie，再走 `AssetManager.openNonAssetFd` 的 STORED 条目定位。平台表使用平台 mount cookie。跟随 [Android 16 ResourcesImpl.openRawResourceFd](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-16.0.0_r2/core/java/android/content/res/ResourcesImpl.java) 的实现，对压缩条目包装 I/O 异常为 `NotFoundException`，缺失 ID 同样抛出。Android SDK 文档对压缩条目描述为 null，此处以该版本 AOSP 的实际代码路径为准。
- `AssetFileDescriptor.createInputStream` 复用已有的有界自动关闭流，限制普通与批量 Java 读取到声明的资源区间。测试生成两个本地 ZIP，后一 mount 故意放置同路径错误内容，验证 alias 仍读取实际所属 APK 的三个字节，且不会读到下一 ZIP 条目。
- `python3 scripts/run_tests.py --test UpstreamResourceAliasTest --strict --out-dir work/upgrade/RES-001/fail-before` 在旧 JAR 上 FAIL，rc=1，stub 未返回描述符。
- `MACAPK_NO_BUNDLE_SYNC=1 runtime/scripts/build.sh` PASS，rc=0，`JARS_ID=787b03ba107af00f`。随后 `python3 scripts/run_tests.py --group offline --strict --out-dir work/upgrade/RES-001/offline-final`，42 PASS、0 FAIL、0 SKIP、15 NOT_RUN，rc=0。真实 Android 设备对照及 GUI 为 NOT_RUN。
