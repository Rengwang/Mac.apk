# ADR-0001：以契约与证据推进现有兼容运行时

- 日期：2026-11-14
- 状态：Accepted（路线决策；实现任务尚未完成）
- 基础提交：`7cb38df7bfcced3412901af262f4d109f6b4f9fc`
- 决策输入：[建议核查](../AI_PROPOSALS_REVIEW_2026-11-14.md)、[路线图](../ROADMAP.md)

## 问题

已有 Framework、原生 shim、Surface 和多进程实现及历史回归，但统一公共测试入口、
能力覆盖与当前性能基线不足。逐应用故障推进使优先级和验收边界难以复用。
完全重写会丢失已有修复，也无法自动消除 Android 与宿主间的语义差异。

## 决策

1. 保留 DEX→JVM/HotSpot、ELF/Bionic 适配和 macOS 后端的主干。
2. 建有版本的契约台账；符号、支持等级与验证状态分开。
3. 使用最小回归与真实 runtime 场景验证；按条件引入 Android 差分和适配 CTS 用例。
4. 只在依赖闭包、许可、正确性与维护成本有证据时选择性移植 AOSP。
5. 首项改进由 ARCH-001 根据代表性 APK 扫描与实跑证据选择。缺失接口和行为错误一起排序，Surface 是候选之一。
6. 当前不引入产品 VM 后端，不自动打桩猜返回值，不修改默认 JVM/图形库版本。

## 比较过的选择

| 选择 | 取舍 |
|---|---|
| 继续只按应用报错修补 | 可快速解决个别故障，但难以证明通用性与不退化；保留应用发现问题的价值，补工程体系 |
| 整体 AOSP/ART/HWUI 迁移 | 依赖与验证面过大；没有证明优于现有实现，不作为当前主线 |
| 全量 Robolectric shadows | 面向测试，含模拟行为和 instrumentation 成本，不是生产 runtime 可替换包 |
| 契约驱动、逐模块收敛 | 可保留已有行为和回退路径；增加测试维护成本，收益可逐卡评估，选择此项 |

## 影响与约束

不承诺任意 APK、CTS 认证、硬件证明或特定性能提升。
不降低既有贡献规则；引用源码逐文件保留来源/许可，不推导商业授权可行性。
普通目录、worktree 和开发工具权限不能替代 OS 强制隔离。
远端 CI 与对照设备是独立能力门槛，不将其未运行状态伪装成 PASS。

## 重新评估条件与回退

若完成足够覆盖的契约/场景测量后，发现现有执行架构存在无法在合理范围修复的通用缺陷，
或单模块 AOSP 试点在正确性、依赖和维护成本上明确占优，可新建 ADR 调整局部选择。
改变产品 VM 边界或第三方主版本需遵守用户授权和项目约定，不由旧报告自动授权。
本 ADR 无运行时副作用；实现逐卡独立提交并保留适用回退路径。
