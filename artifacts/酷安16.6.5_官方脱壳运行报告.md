# 官方酷安 16.6.5 在 Mac.apk 上运行成功

## 成果

官方包：

```text
CoolApk-16.6.5-2610162-coolapk-arm64-sign.apk
com.coolapk.market 16.6.5 (2610162)
```

已重打包并安装为：

```text
/Applications/酷安.app
```

实际运行：主界面正常渲染，话题/关注/头条/热榜/快讯等 Tab 可用，
信息流、图片、评论区都能显示，进程稳定不再闪退。

截图：`酷安16.6.5_官方_Mac运行.png`

## 关键 1：按 4 字节偏移抓 10 个真实 DEX

易盾把真实 DEX 放在匿名 rw-p 内存里，且 DEX 起始地址比页边界早 4 字节：

- 页首是 `30 33 37 00`（即 magic 的后 4 字节 `"037\0"`）
- 真正的 `dex\n` 在页面前 4 字节
- 所以读取 region 后按下面方式重建：

```python
full = b"dex\n" + region[:file_size - 4]
# 再重算 SHA-1（偏移 12）和 adler32（偏移 8）
```

在 MuMu 中抓到 **10 块**：

- 9 块大 DEX（9.0M / 8.4M / 10.1M / 9.8M / 8.1M / 18M / 7.5M / 8.8M / 12M）
- 1 块 1.9M 小 DEX（`classes10`，包含 `wmh` 等启动必需类）

没有第 10 块时，`CoolMarketApplication` 初始化会报
`NoClassDefFoundError: wmh`。

## 关键 2：重打包

1. 用 10 个真实 DEX 替换原 94 MB 壳 `classes.dex`，命名为
   `classes.dex` ~ `classes10.dex`；
2. Manifest 的 Application 从
   `com.netease.nis.wrapper.MyApplication`
   改为
   `com.coolapk.market.CoolMarketApplication`；
3. 删除 `libnesec.so` / `libnesec-x86.so`；
4. 原版 `CoolMarketApplication.onCreate()` 是 native 方法，Mac.apk 没有对应
   native 实现，会抛 `UnsatisfiedLinkError`。已把该方法改成 Java：

```smali
.method public onCreate()V
    .registers 1
    invoke-super {p0}, Landroid/app/Application;->onCreate()V
    invoke-virtual {p0}, Lcom/coolapk/market/CoolMarketApplication;->ޏ()V
    return-void
.end method
```

`ޏ()` 就是反编译里的 `m1131()`，日志会打印
`application init` / `application init end`。

5. 删除 Pangle/广告 native 库：
   `libPglbizssdk_ml.so`、`libpanglearmor.so`、`libpangleflipped.so`、
   `libCtaApiLib.so`、`libtobEmbedEncrypt.so`、`libCPS.so`、`libEncryptorP.so`。

   之前“打开几秒就闪退”就是 Pangle native 库在 Mac.apk 上触发 SIGILL；
   删除后主界面稳定运行。

6. zipalign + apksigner 重签；
7. 原厂证书覆盖：
   `~/Library/Application Support/Mac.apk/signature-overrides/com.coolapk.market.bin`
   已存在，`getPackageInfo(GET_SIGNATURES)` 返回 CoolApk 官方证书。

## 详情页白屏（2026-10-26 追查）

主界面正常后，点具体帖子仍然是白屏。追查结果：

```text
starting activity com.coolapk.market.view.feed.FeedDetailActivityV8
[W] ActivityHost: onCreate threw java.lang.UnsatisfiedLinkError:
    'void com.coolapk.market.view.feed.FeedDetailActivityV8.onCreate(android.os.Bundle)'
    at FeedDetailActivityV8.onCreate(Native Method)
```

`FeedDetailActivityV8.onCreate` 是 **native 方法**，和之前
`CoolMarketApplication.onCreate` 一样，Mac.apk 没有对应的 native 实现。

尝试把它改成：

```smali
invoke-super {p0, p1}, Lcom/coolapk/market/view/base/AlphaToolbarActivity;->onCreate(Landroid/os/Bundle;)V
return-void
```

结果：

```text
FeedDetailActivityV8 called finish() during onCreate
```

因为 native onCreate 里包含 setContentView、解析 intent、挂 Fragment 等全部初始化，
super 里没有这些，Activity 直接 finish，仍然白屏。

`DynamicNodePageActivity` 也是 native onCreate，同样 finish。

结论：

- 这是 **native 方法虚拟化**（Dia/PairIP 一类），不是 Pangle 广告库；
- 主界面大量方法是 Java，所以主界面正常；
- 详情页的入口方法是 native，Mac.apk 没有 ART/VM 实现，框架层无法补；
- 删广告库只能解决主界面 SIGILL，解决不了详情页。

可行路线：

1. 详情页用 c001apk（已验证可用）；
2. 找更老、详情页 onCreate 还是 Java 的官方酷安版本；
3. 逆 native VM / 补 Mac.apk 的 native 方法分发（工作量大，不建议）。

## 详情页追查（二）：isTaskRoot Bug 已修，但仍缺 feed 数据

### 已修：Mac.apk 的 isTaskRoot 永远返回 true

`BaseActivity.onCreate` 里有：

```smali
if (savedInstanceState == null && isTaskRoot() && ࢺ()) {
    TaskStackBuilder ... MainActivity
    finish()
}
```

`ࢺ()` 恒为 true，而 Mac.apk 的 `Activity.isTaskRoot()` 原先**恒为 true**。
于是详情页一进入 onCreate 就被当成“从桌面重复启动”，立刻 `finish()`。

已修：

- `Activity` 增加 `macapkTaskRoot` 字段；
- `ActivityHost.performLaunch` 用 `stack.isEmpty()` 标记根 Activity 与子 Activity；
- 详情页现在 `isTaskRoot()==false`，不再 `finish()`，窗口能停留在详情 Activity。

### 仍白屏：Intent 里只有 feedId，没有 Feed 对象

日志打印详情 Activity 的 extras：

```text
Bundle[{extra_detail_type=null, extra_scroll_goods_feed_id=null,
        extra_from_api=/v6/main/indexV8?...,
        extra_flag=0, extra_reply_id=null, extra_history_id=null,
        extra_notice_id=null, extra_trace=null,
        extra_feed_id=74620681}]
```

只有 `extra_feed_id`，没有 `Feed` Parcelable。
原版 native `FeedDetailActivityV8.onCreate` 会：

1. 取 `extra_feed_id`；
2. 发网络请求/查数据库拿 Feed；
3. 写入 `FeedDetailV13ViewModel.feedFlow`；
4. 再调用 `ಀ()` 挂 `FeedDetailFragmentV8`。

我们只补 `super.onCreate + ಀ()` 时，`feedFlow` 是 null，`ৼ()` 返回 null，
Fragment 挂不上去；直接调 `FeedDetailFragmentV8$Ϳ.Ԩ(feed, 8)` 也会因为
feed 为 null 抛 NPE。

所以“几十行 Smali 胶水”还缺**第 2 步的 feed 拉取/ViewModel 初始化**，
这不是纯 UI 拼接，需要复刻它的 API 请求或从 native 中取回 Feed。

### 当前状态

- 主界面：正常；
- 详情页：Activity 不再闪退/finish，但由于没有 Feed 数据，仍然白屏；
- Mac.apk 的 `isTaskRoot` 通用 Bug 已修，对以后所有“详情页自动 finish”的 App 都有用。

## 详情页修复成功（2026-10-26）

关键不是 `feed` Parcelable，而是 Intent 里只有：

```text
extra_feed_id=74620681
```

原版 `FeedDetailActivityV8` 的 native onCreate 实际做的是：

1. 从 Intent 取 `extra_feed_id`、`extra_reply_id`、`extra_notice_id`、
   `extra_from_api`、`extra_history_id`，写入 `ޑ/ޒ/ޓ/ޔ/ޕ` 字段；
2. 调用类内已有的 `ྈ()` 网络加载方法；
3. `ྈ()` 请求详情，数据回来后自动挂 `FeedDetailFragmentV8`。

最终 Smali：

```smali
invoke-virtual {p0}, Landroid/app/Activity;->getIntent()Landroid/content/Intent;
move-result-object v0

const-string v1, "extra_feed_id"
invoke-virtual {v0, v1}, Landroid/content/Intent;->getStringExtra(Ljava/lang/String;)Ljava/lang/String;
move-result-object v1
iput-object v1, p0, Lcom/coolapk/market/view/feed/FeedDetailActivityV8;->ޑ:Ljava/lang/String;

# 同样写入 ޒ/ޓ/ޔ/ޕ ...

invoke-virtual {p0}, Lcom/coolapk/market/view/feed/FeedDetailActivityV8;->ྈ()V
```

配合之前修好的 Mac.apk `isTaskRoot`，详情页不再 finish，也不再白屏。
